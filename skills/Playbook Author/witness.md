# Witness audit

- Can every file this audit needs be read? Yes: read the Key files and record the findings; write the Standards pointer in Context per `standards/playbook.md`, as a path that opens, distinct from Key files. No: name the unreadable file and stop.
- Does the cited system's own record, schema, code or capture settle the claim? Yes: cite the line and name that file as binding. No, or records disagree: leave the claim open, naming them. A summary is only a pointer: open the file it stands for before stating the claim.
- Will the build install a third-party package? Yes: read behaviour from the version it will install, its shipped code and its answers when run, naming that version beside each claim; another version's capture, a README or a research summary is only a pointer. No: use the system's own record. Version unknown: ask and state no package claim until it is named.
- Does source appear to impose a limit? Yes: trace its call sites and read the neighbouring module for the same feature before stating it. No: go on. Is the claim that a capability is absent? Yes: search for it; for a package, search the whole selected version, not one record. No: go on.
- Is a downstream user's reported fix being proposed as a rule? Yes: keep it a hypothesis until measured on more than that user's pages; plan only what the measurements support. No: go on.
- Does the plan use an address a person named? Yes: check its domain against the account's zone list before it enters the plan. Listed: record that. Not listed: ask before treating it as theirs. No: go on.
- Is another session editing a cited source? Yes: cite the commit read and re-read the source when the build starts. No: cite the source normally.
