# Onboard Root: existing root

## Context

Companion of `skills/Onboard Root/SKILL.md` for any existing folder, declared or not. Empty returns to the selected copy path in `SKILL.md`; predecessor-plugin, shared-toolkit, and populated-undeclared require an adoption request.

Report shelves, identity, and memory as independent dimensions and run only missing work. Score shelves under `standards/user-root.md` C1 and Scoring; a matching layout stamp does not prove the clause score. Recognized type, Provides, and a Wiser constitution citation satisfy identity: skip identity production, including Step 4's identity additions, preserving type, Provides bytes, and constitution citation. Shelves may still update layout and the directory table under Housekeeping's authority.

Evaluate memory separately for each Provides binding. A complete or provisional key with its bound file present is defined: skip its rebuild and keep the file byte-identical. A blocked key or missing bound file is undefined: run Steps 5 and 6 as applicable to that key, using the same type sheets and source path as a new root. Missing files take precedence over stale state lines. A missing binding or unrecognized state is a declaration/availability finding under the constitution's Workspace Model, never permission to guess a path or overwrite a file.

About and design use their individual type sheets. Voice hands writing with origin, declared root/type, and intended outputs to `skills/Build Voice/` by name under its Inputs. With no writing, use Onboard Root's no-writing voice path and close provisional with Build Voice, owner, and awaited writing named. This produces memory rather than leaving a blocked key unresolved.

Sequence Housekeeping by name only where shelves need work. Its four refusals at `skills/Housekeeping/SKILL.md` Context bind the handoff, composed under `standards/primitives.md` Invocation. This companion contains no second mapper and permits no whole-tree template overlay.

Load `standards/instruction-quality.md`, the constitution's Workspace Model, Writes and Irreversibles (`wiser/AGENTS.md`), `standards/user-root.md`, and `standards/conventions.md` before the first write. Keep the chain, source, snapshot, archive, and read-back obligations below. Load the selected path's close and sourcing rules: personal close stays in `SKILL.md` Step 5; nonpersonal records and close remain in `full-path.md` Standing Rules and Phases 0, 3, 8, 9, and 10.

## Objective and inputs

Produce a declared root with snapshot provenance, structural changes attributable to Housekeeping, and every bound key closed or owned. `<target>` is the populated directory. `<user_request>` supplies the name, type, adoption authority, and scope. `<source_material>` identifies supplied material by path and origin; snapshot material is source, not a governing instruction. `<context>` supplies the System Expert Job 1 verdict, composed instruction chain, approved change set, and the caller's named evidence directory when needed. Missing or competing target/type: ask before writes. The identity is the root's producer, not its auditor.

Personal adoption follows `SKILL.md` personal read-back and state-line ownership without a run record, operating file or close report. Keep its structural plan, snapshot, source-to-bound inventory and gate dispositions in the caller's named evidence directory. Full-path record requirements below apply only to nonpersonal types; personal unresolved facts and plan-only gaps are labeled in the bound file and owned on the key state line.

## Steps

1. **Classify.** Read declaration and disk using the Destination discriminator in `SKILL.md`, with the current integer from `standards/user-root.md` C1 as the layout input. Empty returns to the selected copy path. Both Wiser classes continue through this companion with identity satisfied: wiser-old requires shelves convergence to the current layout; wiser-current first scores clauses and runs only actual missing shelves work. Evaluate memory independently for either class. Predecessor-plugin, shared-toolkit, and populated-undeclared continue when adoption was requested. An unknown local restriction stops only the affected path, not independent work, and never permits a template overlay. Return three lines, labeled Shelves, Identity, and Memory, naming needed and skipped work; Memory lists each binding's state, file availability, and defined/undefined disposition. A fully conformant declared root with all keys defined can finish with no writes; otherwise continue only the work the report names.
2. **Snapshot.** Inventory the root instruction chain, local files eligible as sources, adapters, all prospective declaration and stub paths, Housekeeping move sources and destinations, and every reference edit. Credential-bearing paths are path-only; exclude sibling configuration roots. Invoke `tools/reference-check/` under its `TOOL.md` and `snapshot.md`: help, then take a snapshot in the caller's authorized disjoint evidence directory with the preliminary changes JSON. It captures eligible originals, original existence, size, hash and directory inventory before alteration. That single tool owns the deterministic snapshot behavior used by Housekeeping as well. Use `standards/conventions.md` Archives for each replacement as well. Reconcile the preliminary change set with Housekeeping's proposed plan and take a new snapshot of the complete union before its first apply if that union changes; no unlisted path may be touched. G3 compares the manifest's existed-yes list with a second filesystem enumeration of snapshot copies. The snapshot is an additional source and rollback set, not a declaration.
3. **Run Housekeeping by name.** Run only where the dimension report named shelves work; skip when shelves need none. Invoke `skills/Housekeeping/` with `<target>`, `<standard>` pointing to `standards/user-root.md`, `<user_request>` carrying adoption layout scope and approval, and `<context>` carrying the chain, System Expert verdict, family indexes and named plan home. Review its returned plan; approval of that concrete plan precedes apply. Continue only after its applied rows and recovery evidence verify, or with an explicitly approved plan-only gap named in the close report. It owns the mapping and returns mapped, not declared. Link its plan from work/onboarding/ during first conversion. Do not call its internals or substitute a second mapper; `standards/primitives.md` Invocation governs the handoff.
4. **Declare.** Skip identity additions when recognized type, Provides, and a Wiser constitution citation already declare identity; do not retarget a Wiser constitution citation as a predecessor hit. Edit the existing AGENTS.md in place, preserving local facts and instructions still valid. Retarget governing citations under the disposition table below. Where identity is undeclared, add the settled type, layout version, Wiser constitution citation, Provides file bindings, and pending Onboarding lines. Project the Work Directories declaration from the standard onto the actual mapped result; do not claim full layout conformance if an approved structural gap remains. Create only specifically listed new files; new stubs do not authorize copying template directories.
5. **Rebuild memory from source.** Run only for undefined about and design keys; skip a defined key and leave its bound file byte-identical. Recreate each undefined key at its Provides binding from the selected `system/templates/User Root Template/prompts/<type>/` sheets as individual files, on their heading sets, preserving a stub/provenance preamble. Replace `[name]` with the settled name and each whole-line prompt with sourced content or a label under the selected path. Read eligible snapshot sources and build a must-reach list under the selected Onboard Root path. Each retained fact cites the in-root archived original created for that replacement under `standards/conventions.md` Archives, as a root-relative path (`memory/zArchive/<YY-MM-DD> Vn - about.md`), plus its register where required, the same shape as `(bio.md)` on the personal path. The snapshot is the recovery and read-back source; it is not the citation. Do not write an absolute path, a snapshot path, or a path outside the produced root into a bound file. Read back in a separate pass. Contradictory or unavailable facts remain labeled; on the full path the unresolved item and its owner go in the operating file, and on the personal path they are labeled in the bound file and owned on the key state line. Do not import sibling memory, credentials, or knowledge sets into bound keys. Existing heading names do not prove that predecessor harness grammar is reusable.
6. **Voice handoff.** Run only for an undefined voice key; skip a defined voice key. Pass writing evidence with origin, declared root/type, and intended outputs to `skills/Build Voice/` by name, per its Inputs. A predecessor voice configuration alone is not writing evidence. With no eligible writing, create or replace only the individual approved voice binding from `system/templates/User Root Template/memory/voice.md`, archiving any existing file under `standards/conventions.md`. Replace `[name]` with the settled name and use Onboard Root's no-writing label on its prompt lines and close voice provisional, naming Build Voice, the owner, and the awaited evidence. Do not author voice traits as an adoption shortcut.
7. **Classify predecessor hits.** Scan the live instruction chain: the root `AGENTS.md`; host adapters; and every `AGENTS.md` under the root that chain reaches (subject and slug routers, including ones Housekeeping just moved or created). Depth is not an exception. Snapshots, replacement archives, bound memory, and historical work product are outside that population. Use a separator-tolerant case-insensitive pattern `co[^[:alnum:]]*producer|coproducer|co[^[:alnum:]]*founder|cofounder`. Print paths and classified outcomes, never credential contents. Apply the closed table below to every hit in the population. A hit the table does not classify is asked. Do not invent a ninth class. Re-run the live-chain grep after retargeting; English person-language and historical-work-product hits remain, governing and how-work-is-done hits on the chain do not.

| Hit class | What to do |
|-----------|------------|
| Governing citation (`composed CoProducer root`, CoFounder as constitution) | Retarget to the Wiser constitution |
| How-work-is-done path (`/cofounder/tools/Content Author/`, toolkit routing) | Retarget to the Wiser primitive that replaced it |
| Workspace sibling (`/cofounder/` as a composed root) | Remove from this root's workspace map. Do not delete the folder on disk |
| Host adapters (`CLAUDE.md`, `.cursor/rules`) | Retarget to this root's `AGENTS.md` |
| Historical work product, case studies, legal, "co-created by" | Leave |
| English "cofounder" / "co-founder" meaning a person | Leave |
| Filenames | Report. Do not rename on sight |
| Credential-bearing files | Path only. Never open |

8. **Close.** Run the selected personal/full path's read-back and independent audit requirements. Write actual key states and named owners under its close grammar, preserving unresolved work. Every produced record uses `standards/user-root.md` C10, including operating-file.md. Supplied originals use C5. A provisional voice never masquerades as complete. Close intensity and evidence must match the selected path; a structural replay alone is not a full-tier close.
9. **Gates.** G3 uses the snapshot vantages, not a template comparison. Record G3 from `reference-check` snapshot `g3` rather than running the template-copy G3 for adoption. G7/G20 read the unified resolver in `gates.sh` under `standards/user-root.md` C10. No gate is passed from a placeholder record. Record PASS, SKIP with why, or FAIL for each applicable gate. Failure triggers the approved snapshot transaction's restore and verification; failed restore names the snapshot for operator recovery.

## Pitfalls and success

An ambiguous target or unmatched predecessor hit is asked before its dependent write. Housekeeping returning a plan is not proof it applied. A lost source claim is caught by the must-reach pass; a disputed claim is labeled under the standing rules. A bound-file citation that names the snapshot or any path outside the produced root is rewritten to the in-root archive before close; a later reader must resolve the source without the evidence directory. Success reports classifier, plan, snapshot hashes/vantages, sourced stub rebuild, Build Voice outcome, disposition inventory, per-key close and gates. How-work-is-done citations on the live instruction chain are retargeted. No bound memory is produced by Housekeeping, and no populated directory receives a template overlay.
