# Build Brand

## Context

Use to build or rebuild the `memory/design.md` of one user root, the file its Provides block binds as `design`, when the person wants more than onboarding's light fill. This skill writes that file; it never writes `voice.md` or `about.md`.

Onboarding's light fill, which the "not now" answer keeps, belongs to `skills/Onboard Root/`.
How a root's writing sounds belongs to `skills/Build Voice/`; `voice.md` is read here, never written.
What is true about a person or brand, personality included, belongs in `memory/about.md`, read here, never written.
A palette belongs to `skills/Color Palette Design/`, a type system to `skills/Typography Design/`, and the token system to `skills/Design System/`, each run by name from this skill.
A design job from a direction already set belongs to `skills/Designer/`.
A generated image belongs to `skills/Media Generator/`.
A drawn still picture belongs to `skills/Illustrator/`, and this skill draws none.
A logo, a symbol or an icon family belongs to `skills/Brand Mark/` where it is installed, and this skill never draws one.
Naming a brand and searching trademarks are not covered here; a stage that meets either names it as a gap.

This skill runs other skills by name where its steps say so, per `standards/primitives.md` Invocation, and never reaches inside them. Its supporting files, all beside this file, are `questions.md`, the question bank; `brand.plan.md`, the Playbook master the full path instantiates; and `parts/`, the parts library with its `build-brand-fonts-1` font pack, installed once and checked against its hashes, whose index `parts/parts.md` lists each type pairing, palette recipe, monogram container and graphic-language set with its tags and its licence. Brand boards are written by `tools/Contact Sheet/`'s `board` layout, which sets each board from the parts named for it, refuses a board that fails the type-to-colour match or the contrast checks, and decides nothing else. A PNG of a page, where one is wanted, comes from `tools/render/` `html`, run by this skill. Its owner and gate is the Creative Director: its Review sees every page of boards before the person does, and its Audit judges the brand in use.

Where the owning root binds an available voice, every sentence this skill drafts for the person to adopt is written through `skills/Content Author/` in that voice, and this skill never writes one itself; without one, Sentences the person adopts says what is offered instead.

Classifier seam: routing, where `hooks/route.mjs` may open this skill for an ask. Else: the routing table, read as `AGENTS.md` states.

## Objective

A `design.md` at the path the owning root binds, with usable rules a skill can apply without opening the answers record, every prompt replaced by a rule or an evidence label from `standards/conventions.md`, and every claim traced in place to a supplied file or a numbered answer. Verified by a separate read-back pass; the person's confirmation closes the brief path or stage 10, while full-path provisional writes follow Step 7 without B8.

On the full path, the run also leaves, kept with the work, the boards and their picks, the brand direction, the token system and a short brand guide for people; `design.md` is written from the same choices as the guide, so the two never disagree.

Three ways this ends, not two.

- **Complete.** The chosen path ran to its end and the person confirmed the read-back; on the simple path, which asks nothing, its separate read-back passed.
- **Provisional.** The full path's Playbook is written and its stages are under way, or the brief path left headings labelled; the file says what it waits on and names the Playbook where there is one.
- **Stopped.** The person stopped, or the evidence never settled; the bound path is left as it was, with no unconfirmed replacement.

## Pitfalls

**An ambiguous request or two possible roots.** Gathering answers before ownership is settled produces the wrong root's brand. Ask before gathering; Step 1 resolves the root once.

**A brand that could be anyone's.** Borrowed words, the field's default colour or a look nobody chose replaced the person's answers. Run the Creative Director's Slop Scan and Purpose Check against its Prohibited Defaults Taxonomy, return unchosen defaults to strong options grounded in the answers, and have the person choose. On the simple path the person asked for the choice to be made: run the same scan on it before the page is shown.

**Deciding for the person.** An agent's recommendation became a rule without a pick. Remove the unchosen rule and offer strong options with reasons; only the recorded choice enters the file. The simple path is the exception the person made: they asked for the choice to be made, and each choice it records as made at their request is a recorded choice.

**A recommendation that pushed.** Several options were marked recommended, one was pre-selected, or a reason did not come from the person's own answer. Mark at most two, say why from their own words, and let them pick.

**A quiz that outlasts the budget.** Follow-ups and confirmation were not counted. Apply Step 3's limit before the next question, label what remains, and offer the full path at the close.

**Asking for personality again.** The five questions were treated as a second about interview. Read `about.md`, ask only how that personality should look, and keep the visual choices here; absent personality is disclosed rather than invented.

**Writing `voice.md` or `about.md`.** Resolving disagreement by editing another key crossed ownership. Leave those files untouched, name the disagreement, and route a requested voice change to `skills/Build Voice/`; about facts stay in their own bound file.

**Drawing a mark or an icon.** A missing installed capability became permission to improvise one. Route to `skills/Brand Mark/` where installed, or name what is owed and make nothing in its place.

**Spending without asking.** A billed call was treated as already authorised because the path was chosen. Stop before the call, state that call's cost and wait for its yes; the full path is not spending consent.

**A claim with no answer number or file.** A synthesis lost its source on the way into `design.md`. Locate the supporting answer or file and cite it in place; where none supports the claim, replace it in place with `[Unverified: requires confirmation]` as Step 7 says.

**Boards that read as one idea.** One palette recipe repeated across options leaves ten boards differing only in type. Cover the five colour energies on purpose and vary palette, type and graphic language together.

**Type that fights its colour.** A loud palette set in a quiet or period face reads as two brands. Let the layout's match check refuse it, and replace the board rather than override the check.

**A page shown before its Review.** A fault the making context's own checks passed reaches the person. Send the page to Review in a second context first.

**A placeholder taken for a logo.** The person picks a board for its monogram. Typeset it, never draw it, and label it a placeholder.

**A texture lost in dark.** A texture matched by a metric is invisible on the person's screen. Ask them, strengthen it and show it again.

**A sentence written in the interview's own words.** A stack of the person's phrases reads disjointed. Follow Sentences the person adopts above rather than assembling the phrases here: through Content Author where a voice is available, otherwise their own words or a working draft marked as such.

**A direction a reader cannot check.** A colour or face whose source is not named looks invented. Give every element its answer and pick in the closing table.
