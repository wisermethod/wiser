Every question this skill asks and every pick the person makes is numbered and saved, as it happens, to one dated file per run, `memory/answers/YYYY-MM-DD design answers.md`, in the form `standards/user-root.md` C14 declares. It holds a row for each numbered question and pick, and for the person's own words under the numbers `questions.md` gives them, and nothing else: what the run read and every other observation of the run are not rows, and go where this skill names them. The one exception is the brief path: B1 to B7 are rows of the answers they settle from the supplied files, as `questions.md` and `paths/brief.md` specify. `design.md` states the results as usable rules, including the chosen sentence and core words themselves, colour values, typefaces and picks, each citing its answer number in place and naming the dated record so it resolves. It never reproduces an answers-file row: the question, what was shown or its status. Stating the chosen result is not copying that row. Is a file of that name already there from another run today? Yes: before saving, offer the named ask **update root**, as C14 says; do not create `memory/answers/` here or apply the update. Applied: save as above. Declined or not applied: write no answers file and go on with the run; the bound files it writes stand, each result in `design.md` citing the person's words in place as `(Firsthand: <their name>)` rather than an answer number, and `<requester_words>` taken from the conversation. ## Selector inputs and histories

Selector inputs are JSON objects projected from confirmed results, not the C14 file and not one mutable object shared among commands. Keep a fresh input file for every command beside the work, with its output and the page it produced. Each next answers file carries the returned page switch position as `mode`. The `looks` command always returns `options`, never `options: null`. `paths/sitting.md` names the fields and commands:

| Command | File it reads | Command-specific state |
|---------|---------------|------------------------|
| First `looks` | `looks-answers.json` | Common supported fields with `looks: []`; no `shown`, `steer` or `picks`. |
| Retried `looks` | `looks-retry-<n>-answers.json` | Common fields with `looks: []`, complete look `shown`, current `steer` and `off`; no `picks`. |
| `round1` | `round1-answers.json` | Sentence, words, all taps, `off`, picked `looks`, complete `looksShown`, kept assets, `photoRules` and `heroPhrase`, plus type/name and optional body; never `shown`, `steer` or `picks`; optional `avoid` on a Review retry; persist `pageDisplayed` and, when true, the complete displayed `selection.boards` as `displayedBoards`. |
| `variations` | `variations-<n>-answers.json` | Common fields, picked `looks` and separate `looksShown`, `picks` as the complete step records the member sent, complete board `shown`, current `steer` and `off`; optional `avoid` on a Review retry; persist `pageDisplayed` and, when true, the complete displayed `selection.boards` as `displayedBoards`. |
| `lock.mjs` | `lock-answers.json` | Lock-only enrichment under `lock.md`, with the same `photoRules` retained as evidence and checked against the spec. |

For a Review retry, retain the same command inputs and flags and add `avoid` with the full blocked board records, accumulating any blocked replacements. For an unseen page (`pageDisplayed: false`, the default), exclude every blocked key and build one fresh page with `avoid` empty, then review it again. A displayed page sets `pageDisplayed: true` and saves its complete returned `selection.boards` as `displayedBoards` in that command's answers file before waiting for an answer. Resume reloads both fields: retries start from those saved boards, replace only avoided keys present on that page and keep every other board's bytes except the returned page mode, board and step captions, steps beyond a refused middle step, and Close recommendation flags. Earlier blocked keys cannot select a slot by number. Use the returned form unchanged. A displayed slot exhaustion or an unfillable rebuild is an explicit refusal; retain its exact cause, never assemble by hand. An unseen blocked page and its rejected boards never enter `shown`.

Keep looks history separate from boards history; append each displayed page's returned records unchanged. Round 1 carries looks history only in `looksShown`, never in board `shown`. A congruency pull reaches the first looks and Round 1 through `off`; `steer` is used only by looks retries with nonempty `shown` and by variations. Raw comments stay verbatim in the numbered answers; the selector gets their supported numeric or `off` interpretation only. The photograph rule is required before Round 1 and remains the exact same text in the selected board and lock answers. At a checked-wording correction, keep the original chosen sentence and pairs beside K3's checked version rather than overwriting the member's choice.
