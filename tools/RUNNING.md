# Running a tool

What every script in `tools/` does when you run it. The rules behind this page are `standards/script-contract.md`.

- **Help needs nothing installed.** The script's `help` command answers on a fresh copy, before any package or configuration is looked for.
- **An unknown flag is refused by name**, before any work or any network request, and the refusal points at `help`. A mistyped option never looks like it applied.
- **The plugin asks once before it installs.** The first command that needs packages, in this copy, reports what it would fetch, from where, into which directory, and how large it is, then stops with exit 1. That report is the question. Re-run the same command with `--install` and it installs, finishes the work, and writes `.wiser-consent` at the plugin root; later tools in this copy install without asking. Set `WISER_ALLOW_INSTALL=1` for an unattended run. A copy whose marker names a different path asks again. `tools/AGENTS.md` lists every write an install makes and every host it reaches. A later tool in the same copy installs without stopping and says so on stderr, `First run: installing dependencies` and where; its result on stdout is unchanged.
- **An install that fails names the cause**: Node older than 18, a directory this account cannot write, or a lockfile out of step with its manifest. To retry, delete the tool's `node_modules/` so a half-finished install cannot mask the result, fix the cause, and run the same command with `--install` again.
- **A system dependency is named, not installed, and it is once per machine** where a tool's own packages are once per copy of the plugin. A tool that needs something beyond Node, such as ffmpeg or a Python interpreter, names it in its `TOOL.md` with the one command that proves it present, and a missing one fails by naming it. No tool carries install steps for your machine.
- **Credentials arrive as a file path.** A command that needs configuration takes `--env <absolute path>`; the tool reads that file and never searches for one, and its values never reach the output or a log. No tool in this release needs one.
- **Success is one JSON object on stdout and exit 0.** Failure prints to stderr, leaves stdout empty, and exits 1, naming the cause and the fix. A `check` command exits 0 either way and puts its verdict in the JSON, so read the field, not the exit code.
- **Every path is absolute, and files land only where you point.** A relative path is refused by name, because it would resolve against whichever directory you happened to be in. A tool writes its deliverable to the path you pass and nothing inside its own directory beyond its packages; a path inside the tool directory, or one that resolves onto a credential file, is refused.
- **A tool that cannot run says so itself**, rather than returning something wrong. What the primitive that called it does next is the constitution's rule.
