# Running a tool

What every script in `tools/` does when you run it. The rules behind this page are `standards/script-contract.md`.

Each tool's `runs:` key declares whether it also runs on Wiser's side; the rule is in `standards/primitives.md` Frontmatter.

- **Help needs nothing installed.** The script's `help` command answers on a fresh copy, before any package or configuration is looked for.
- **An unknown flag is refused by name**, before any work or any network request, and the refusal points at `help`. A mistyped option never looks like it applied.
- **Commands that carry their packages need no install question.** `data` ships its compiled package. Content Harvester carries `dist/harvest.mjs`: `help`, `sample`, `validate`, `run --dry-run` and unproxied `run` need no package install. A proxied `run` alone needs external `undici`, selecting the first non-blank trimmed `HTTPS_PROXY`, `https_proxy`, `HTTP_PROXY` or `http_proxy`, as sitemap does; `NO_PROXY` does not bypass it. keynote-render carries `dist/render.mjs` with `yaml`: every command, including `--brand`, needs no package install; `help` and `check` open no Keynote application, while `themes`, `layouts`, `build`, `inspect`, `snapshot`, `export`, `sync`, `update-slide`, `insert-slide` and `delete-slide` still need the member’s Mac, osascript, Keynote and Automation permission. `tag-audit audit` uses Node fetch unless its selected proxy variable is non-blank; a proxied audit retains the `undici` install path. `deck-export scaffold` works in both starter and template modes without packages or a browser. Its reveal.js files and render's Mermaid browser file are carried with the tools, with hashes and notices beside them. `render html`, `svg`, `mermaid`, `url`, and `deck-export pdf` and `png` still need the shared browser runtime and Chromium when absent. Both tools' `check` commands survey without installing; `check --install` repairs the browser. Carried copies are refreshed only by developers, never during a member command.
- **The plugin asks once per person before it installs, while consent persists.** The first command that needs packages reports what it would fetch, from where, into which directory, and how large it is, then stops with exit 1. The refusal opens with a question written for the member; say it to them word for word (for Form `ask`, its `question` field), and use the details after it only to act on their answer or if they ask. Re-run with `--install` and it installs, finishes the work, and writes `.wiser-consent` in the platform user-config directory and at the plugin root. Later tools in every copy install without asking; a copy marker whose realpath matches is also accepted. Claude Cowork loses installs and consent between cloud sessions, so obtain consent again when the next session needs an install. The person marker can fail to write, including when the user-config directory is linked, owned by another user or writable by group or others. Then the authorised run says so on stderr in one line with the reason: the copy marker covers this copy alone where it could be written, and otherwise this run alone. Set `WISER_ALLOW_INSTALL=1` for an unattended run. `tools/AGENTS.md` lists every write and host. An install says `First run: installing dependencies` and where on stderr; its result on stdout is unchanged.
- **The app owns the runtime.** In Claude Cowork, an installed plugin's scripts run in a cloud session on its own Node 22; it offers no local MCP server, and its default download list blocks Playwright's hosts. Browser tools use the browser Cowork already holds, with no download, and their pictures reach the attached folder; Cowork can change or drop that browser at any image update. The ChatGPT desktop app ships Node with no npm, so a tool with its packages built in needs only `node`, with no package install or consent prompt.
- **An install that fails names the cause**: Node older than 18, a directory this account cannot write, or a lockfile out of step with its manifest. A failed shared browser install removes its temporary directory; fix the cause and run the same command again. Content Harvester's proxy-only install also runs in a temporary directory, removes it on failure, and leaves the tool's manifest and lockfile unchanged: fix npm's reported cause and retry the same command, keeping the tool's existing `node_modules/`. For a full tool-local install, remove the incomplete `node_modules/` in the directory the error names before retrying with `--install`.
- **A system dependency is named, not installed, and it is once per machine** where a tool's own packages are once per copy and the shared browser runtime is once per person. A tool that needs something beyond Node, such as ffmpeg or Python, names it in its `TOOL.md` with the one command that proves it present, and a missing one fails by naming it. No tool carries install steps for your machine.
- **Credentials arrive as a file path.** A command that needs configuration takes `--env <absolute path>`; the tool reads that file and never searches for one, and its values never reach the output or a log. No tool in this release needs one.
- **Success is one JSON object on stdout and exit 0.** Failure prints to stderr, leaves stdout empty, and exits 1, naming the cause and the fix. A `check` command exits 0 either way and puts its verdict in the JSON, so read the field, not the exit code.
- **Every path is absolute, and files land only where you point.** A relative path is refused by name, because it would resolve against whichever directory you happened to be in. A tool writes its deliverable to the path you pass and nothing inside its own directory beyond its packages; a path inside the tool directory, or one that resolves onto a credential file, is refused. Omitted speech-model `--model-cache` uses the person-scoped `models/` folder in `tools/AGENTS.md`; an explicit absolute path still wins.
- **A tool that cannot run says so itself**, rather than returning something wrong. What the primitive that called it does next is the constitution's rule.
- **A command-line tool's sandbox can refuse a tool that listens on this computer.** Codex's default sandbox refuses a command that serves a page or takes a callback on a local port, with its network access on or off (Codex 0.164.0, measured 2026-10-26). A tool that listens reports that refusal as an answer of its own, naming the error, and leaves nothing running, as the Form tool's `no-listen` does; the command can run again outside the sandbox where the command-line tool allows one command out. A Codex set to full access never meets the refusal, so a run there proves nothing about a member's default.
