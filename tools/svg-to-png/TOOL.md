# svg-to-png

One PNG written from one SVG, at the dimensions the SVG declares for itself multiplied by a scale factor, or at an exact pixel width the caller names.

## Context

Use it whenever vector artwork has to arrive somewhere as pixels: a diagram or logo bound for a deck, a document, or a surface that will not display SVG; a high-resolution export of an asset that exists only as vector; an SVG whose text depends on webfonts, which a fontless converter silently reflows into a different image.

Do not use it for a different input. An HTML page, a Mermaid diagram, and a live URL each have their own render tool (`html-to-png`, `mermaid-to-png`, `web-screenshot`); an existing raster is resized, cropped, or converted by `image-edit` and composited by `image-overlay`; an image that does not exist yet is generated by the `Media Generator` skill, not here. Do not reach for it to change the artwork either: it renders what it is handed and edits nothing in the input.

It authenticates to nothing, holds no credential, reaches no other primitive, and starts no request of its own. It reads the one file the caller names and writes the one file the caller names. Rendering happens in a headless browser, so an SVG that references a remote font or a remote image causes that browser to fetch exactly the addresses written inside the SVG; an SVG that references nothing outside itself puts no traffic on the network.

## Sizing

Output pixels come from the SVG's own dimensions, and the JSON reports which of the three answered as `sizedFrom`.

| `sizedFrom` | Dimensions read from | Applies when |
|-------------|----------------------|--------------|
| `attributes` | The root `<svg>` tag's `width` and `height` | Both are present and absolute; a `px` suffix and a decimal are fine |
| `viewBox` | The last two numbers of the root tag's `viewBox` | The pair above is absent, incomplete, or relative |
| `default` | An 800 by 600 canvas | The tag states neither, so the artwork is laid out on a canvas rather than measured |

Only the root tag is read. A `width` on a shape inside the document describes that shape, and a percentage states a share of a container this render does not have, so both read as absent and the chain falls through rather than sizing to a number that meant something else.

The output is then that size times the scale, rounded to whole pixels. `--scale` defaults to 2, which is the useful default because a 1x raster of vector artwork looks soft on the displays these files end up on. `--width` overrides it: the scale becomes whatever puts the SVG at that exact width, and the height follows so the aspect ratio holds.

What makes the drawing grow with the canvas is the `viewBox`, which maps the drawing's own coordinates onto whatever size the viewport is given. An SVG that declares dimensions but no `viewBox` has no such mapping, and enlarging its viewport would enlarge the canvas while leaving the artwork at its original size in the corner. So the copy handed to the browser gets a `viewBox` built from the dimensions above whenever the root tag carries none. The file on disk is never touched.

## Quick Start

```bash
node scripts/render.js help
```

Usage text, with nothing installed.

```bash
node scripts/render.js render --file /path/to/a/work/directory/diagram.svg --output /path/to/a/work/directory/diagram.png
```

The first real run installs Playwright in this tool's directory and asks for a re-run; the second does the work and prints one JSON object:

```
{"output":"/path/to/a/work/directory/diagram.png","width":1600,"height":1200,"scale":2,"sizedFrom":"attributes"}
```

Anything else, see Troubleshooting.

## Dependencies

| Dependency | Needed for | Present when |
|------------|------------|--------------|
| Chromium (Playwright browser) | `render` | `npm run check:chromium` exits 0 with `"chromiumLaunch":true` |

Presence is a **trial launch** via the shared browser-runtime (`scripts/lib/browser-runtime.js`), not a path on disk. Missing OS libraries are self-healed in userspace where a C compiler is present; otherwise the check names the library and the one next step. Install steps are never written here.

## Usage

| Command | Purpose | Needs a browser |
|---------|---------|-----------------|
| `node scripts/render.js help` | Print usage and exit | No |
| `node scripts/render.js render --file <path> --output <path>` | Render the SVG and write the PNG | Yes |

Options:

| Option | Effect | Default |
|--------|--------|---------|
| `--file <path>` | The SVG to render, an absolute path. Required by `render` | None; required |
| `--output <path>` | The PNG to write, an absolute path to a file ending in `.png`, outside this tool's directory. Missing parent folders are created | None; required |
| `--scale N` | Multiply the SVG's own dimensions by N | `2` |
| `--width N` | Render at exactly N pixels wide, height following the ratio. Overrides `--scale` | None; `--scale` decides |
| `--timeout N` | Milliseconds the page may take to load whatever the SVG references | `30000` |
| `--overwrite` | Replace an existing file at `--output` | Off; an existing file is refused |
| `--help` | Print usage and exit | Off |

One file per run, and no default output location: the caller decides where the PNG lands, per the work-directory rule in `standards/conventions.md`. `--output` names the file itself, not a folder to put it in, so the run and the path agree on what will exist afterward. Both paths are absolute, because a relative one resolves against whichever directory the caller happened to be in.

A run whose `--output` already exists refuses, names the path and the flag, and writes nothing. `--overwrite` is the plain opt-in that lets it replace the file: re-rendering the same artwork is cheap, and the file already sitting there may be the only copy of something that was not. The refusal costs no install and starts no browser, so a second run with the flag is the whole fix.

`--timeout` moves a budget the render already ran under rather than adding one: the page holding the SVG has always had 30 seconds to fetch whatever the file references, and the flag makes that number the caller's. It bounds the load, not the whole command; a render that finishes loading and then takes a while to paint a large canvas is not what this budget stops.

This tool needs no credentials and no configuration file, so no command takes `--env` and nothing here resolves a Provides binding.

## Script Contract

Every script in this tool follows `system/templates/Script Contract.md`: self-contained imports, help answered before the dependency check, the first-run install, the declared system dependency checked only on the command that needs it, and the stdout and stderr rules. Argument checks that need nothing installed run before the install too, the overwrite refusal among them, so a mistyped path or a target that is already taken costs no download and starts no browser. The sections above state what the command does; the contract states how the script behaves getting there.

`node --test` runs the sizing rules against their own cases with nothing installed, because the decisions about dimensions, scale, the output path, the load budget, and the shape of the page the artwork is laid on all live in a module the browser never touches. One of those cases holds the page to a definite width: an SVG whose width is left to be resolved from its content contributes a CSS default of 300 by 150 and would cap every render at 300 pixels.

## Output

One JSON object on stdout and one PNG on disk, exit 0.

| Field | Carries |
|-------|---------|
| `output` | The absolute path written |
| `width`, `height` | The PNG's pixel dimensions |
| `scale` | The factor actually applied, which is the derived one when `--width` was given |
| `sizedFrom` | `attributes`, `viewBox`, or `default`, per Sizing above |

A run that cannot produce the image writes no PNG, prints nothing to stdout, and exits 1. `sizedFrom: "default"` is the field to read when an image comes out an unexpected size: it means the SVG declared nothing and the fallback canvas decided.

## Troubleshooting

| Message | Cause | Fix |
|---------|-------|-----|
| `Dependencies installed. Re-run the command.` | First run in this copy | Run the same command again |
| `npm ci failed` | Node missing or older than 18, the directory is not writable, or `package-lock.json` is missing or out of step with `package.json` | Confirm `node --version` is 18 or newer and that the lockfile is present and matches the manifest, which `npm ci` requires and will not resolve around; then delete `node_modules/` and run `npm ci` here by hand |
| `Error: --file is required.` | `render` ran with no SVG to read | Pass `--file <path>` |
| `Error: --file must be absolute` or `--output must be absolute` | A relative path was passed | Pass the absolute path; do not rely on the working directory |
| `Error: no file at <path>` | The input path does not exist | Check the path; an absolute one cannot be misread |
| `Error: <path> holds no <svg> element` | The file is not SVG, or a raster or an HTML page was passed | Pass an SVG; a renamed PNG belongs to `image-edit` and an HTML page to `html-to-png` |
| `Error: --output must end in .png` | The output was named for a format this tool does not write | Rename the target `.png`; a JPEG of this artwork is `image-edit`'s job after the render |
| `Error: <path> already exists` | A file is already at `--output` and this run would have replaced it | Pass `--overwrite` to replace it, or name a path that is free |
| `Error: --output resolves inside this tool directory` | The output path landed in the shared root | Pass a work directory in the owning root |
| `Error: --scale must be a positive number` | The value was zero, negative, or carried a unit | Pass a bare positive number, `2` or `1.5` |
| `Error: --timeout must be a positive whole number` | The value was zero, negative, fractional, or carried a unit | Pass milliseconds as a bare whole number, `30000` |
| `Error: Chromium cannot launch` | Binary missing, launch blocked, or OS library gap | Follow the `remediation` line from `npm run check:chromium` |
| `Error: <path> did not finish loading within <N> ms` | A font or image the SVG references is slow or is never going to answer | Confirm the address is reachable, embed the asset in the SVG, or raise `--timeout` |
| `Error: could not render <path> at <W>x<H>` | An SVG reference that fails outright, or an output size past what the browser will allocate | Remove or localize the failing reference; lower `--scale` or `--width` |
| `Error: unknown option "<flag>"` | A misspelled or invented flag | Check `help`; the flag was refused rather than ignored |
| Text renders in the wrong typeface | The webfont the SVG names did not arrive before the screenshot | Confirm the font URL is reachable from this machine, or embed the glyphs in the SVG |
| The PNG is 1600 by 1200 from an SVG that looked smaller | Expected: `--scale` defaults to 2 | Pass `--scale 1` for pixel-for-pixel output |
| The artwork fills a small part of a large PNG | The SVG declared no size, so the 800 by 600 fallback canvas applied and the drawing occupies whatever share of it its coordinates ask for | Give the SVG a `viewBox` or a `width` and `height` that bound the artwork |

## Success

- `help` prints usage to stdout and exits 0 on a copy with no `node_modules/` and no browser.
- `render` against a well-formed SVG exits 0 with one parseable JSON object on stdout and a PNG at `--output` whose pixel dimensions equal the reported `width` and `height`.
- An SVG declaring `width` and `height` renders at those dimensions times the scale; the same file with `--width N` renders exactly N wide with its aspect ratio intact; an SVG declaring only a `viewBox` sizes from it, and one declaring neither reports `sizedFrom: "default"`.
- The artwork itself grows with the canvas: the same drawing at `--scale 1` and `--scale 2` differs in resolution, not in how much of the frame it fills, whether or not the file declares a `viewBox`. The dimensions in the written PNG's own header, not only the reported ones, change with the scale.
- `render` with `--file` or `--output` omitted, with a relative path, with a path that does not exist, or with an output that resolves inside this tool directory exits 1 with the cause on stderr and stdout empty, and triggers no dependency install and no browser start.
- `render` against an `--output` that already exists exits 1 naming that path and `--overwrite`, leaves the existing file byte-identical, and starts no browser; the same run with `--overwrite` replaces it and exits 0.
- `render` whose `--output` sits under folders that do not exist yet creates them and writes the PNG there.
- `--timeout` bounds the page load and defaults to 30000 ms; a run against an SVG referencing an address that never answers exits 1 naming the budget, and lowering the flag reaches that failure sooner.
- A run against an SVG that references nothing outside itself completes with no network request; a run against one that references a remote asset requests only the addresses written in that SVG.
- No run reads a credential, and no run writes any file other than the caller's PNG and what `tools/AGENTS.md` lists a first run installing, including the browser build outside this plugin, in this tool's own directory.
