# Hooks

Two hooks ship here, and they exist for the classifier. `hooks.json` registers both with a harness that loads plugin hooks.

| File | Runs when | What it does |
|------|-----------|--------------|
| `session.mjs` | A session starts, resumes, clears, or compacts | Writes the session binding, then drops bindings whose harness is gone and bindings older than seven days |
| `route.mjs` | A request is submitted, before the model starts | Writes the same binding, then puts the ask to `wiser.route.ask` through the gateway and, when the answer is confident and names a primitive in this root's indexes, adds one line naming that file. `wiser/AGENTS.md` `## Classifier` is what the line serves |

**The session binding is the one inventory for this machine-state write.** It lives under the gateway home at `classifier-sessions/`, mode 0600 in a 0700 directory. Other files point here; they do not restate the record. A binding, `<session_id>.json`, records the session, the harness process and the start time the OS reports for it, the working folder, the composed roots, the owning root when exactly one of those roots is a candidate, whether the session is refused and the first cause (`at-or-above`, `descendant`, or `scan-cap`), and when it was written. A pointer, `current-<harness_pid>.json`, names the session that process is running now. Both hooks write the binding and then the pointer whenever `<home>/classifier-status/claude-code.json` exists, whether or not it says attached and whatever the refusal. No presence file, no write.

**`route.mjs` prints nothing and sends nothing** unless the binding it just wrote verifies, is not refused, and names at least one root, and the gate that was already here also passes: the presence file says a classifier is attached and its process is alive, the working folder sits inside an owning root, and nothing at or above that folder declares `classifier_refusal: yes`. A plugin root and a workspace folder declare no `type:`, so a session started in one sends nothing on this hook, because the root that will own the request is not yet known. The binding is still written.

**It does not send the named asks** `wiser/AGENTS.md` lists, whole or with more words after them, which are handled before any call is made, and **it does not route to a tool**: a request enters at a skill or an expert, so a tool answer leaves the routing table to be read as today. Its line defers to the request: it names a file to load unless the request names another, or names an output that file does not yield.

**With no classifier attached** the route hook still starts on every request and exits at once: about one short Node process, no output, and no tokens. The session hook does the same when no presence file exists.

**What a hook cannot know.** A directory added mid-session with `/add-dir` is not on the harness process's argument list and is not in the settings files the hook reads, so it is not in `roots`. A tool still checks its own material's location against the roots the binding does hold, and a refusal at that location sends nothing. The candidates the hook can see are the working folder, every `--add-dir` on the harness process, and `permissions.additionalDirectories` in the user and project settings. Where those yield one root, it is the owning root. Where they yield several, or none, the owning root is not established: a hook cannot ask the person, and a caller that does not name one of the roots sends nothing. **A gateway started with its own `--home` or `--env`** is not found, and the hook is then silent rather than wrong. **A harness that sets no `CLAUDE_PID` (Codex, Cursor) does not run these hooks, so it writes no binding, and every seam is silent there.**

`lib/` holds what the hooks share: the binding, the presence and ownership checks, the roster built from the three family indexes, the one-shot gateway call, and the runner that keeps any error or timeout silent. `test/` runs offline: `WISER_HOOK_STUB_FILE`, a JSON file of answers by action id, stands in for the gateway, and is read only when that variable is set.
