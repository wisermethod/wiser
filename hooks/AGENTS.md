# Hooks

Two hooks ship here, and they exist for the classifier. `hooks.json` registers both with a harness that loads plugin hooks. Registration is unconditional.

| File | Runs when | What it does |
|------|-----------|--------------|
| `session.mjs` | A session starts, resumes, clears, or compacts | Writes the session binding, then drops bindings whose harness is gone and bindings older than seven days |
| `route.mjs` | A request is submitted, before the model starts | Writes the same binding, then puts the ask to `wiser.route.ask` through the gateway and, when the answer is confident and names a primitive in this root's indexes, adds one line naming that file. `wiser/AGENTS.md` `## Classifier` is what the line serves |

**The session binding is the one inventory for this machine-state write.** It lives under the gateway home at `classifier-sessions/`, mode 0600 in a 0700 directory. Other files point here; they do not restate the record. A binding, `<session_id>.json`, records the session, the harness process and the start time the OS reports for it, `hook_started_ms` from the start of the hook, the working folder, the composed roots, the owning root when exactly one of those roots is a candidate, whether the session is refused and the first cause (`pending`, `unresolved-add-dir`, `at-or-above`, `descendant`, or `scan-cap`), and when it was written. A pointer, `current-<harness_pid>.json`, names the session that process is running now and carries the same `hook_started_ms`. Both hooks write whenever `<home>/classifier-status/claude-code.json` exists, whether or not it says attached and whatever the refusal. No presence file, no write.

**The first write is pending**, before the hook reads the harness arguments, the settings files, or walks any tree: `pending: true`, `refused: true`, `refused_by: pending`, `roots: []`, `owning_root: null`, then the pointer naming this session. The final binding is written only when that pointer still names this session. A reader treats `pending: true` as not sendable (reason `pending`). A writer does not replace a pointer whose `hook_started_ms` is newer than its own. It re-reads the pointer after the atomic rename, and when a newer one is there it restores nothing and reports that it lost.

**`route.mjs` prints nothing and sends nothing** unless the binding it just wrote verifies, is not refused, and names exactly one owning root, and the gate that was already here also passes: the presence file says a classifier is attached and its process is alive, the working folder sits inside an owning root, and nothing at or above that folder declares `classifier_refusal: yes`. A plugin root and a workspace folder declare no `type:`, so a session started in one sends nothing on this hook, because the root that will own the request is not yet known. The binding is still written. Several composed roots, or none, leave `owning_root` null. Every classifier path is then silent (`no-owning-root`), a caller-named root included. A caller-named root is only an equality check against that one `owning_root`.

**It does not send the named asks** `wiser/AGENTS.md` lists, whole or with more words after them, which are handled before any call is made, and **it does not route to a tool**: a request enters at a skill or an expert, so a tool answer leaves the routing table to be read as today. Its line defers to the request: it names a file to load unless the request names another, or names an output that file does not yield.

**With no classifier** the two hooks still start one short Node process each (per request, and per session start, resume, clear or compact), write nothing and print nothing.

**Composed directories** are the working folder, every `--add-dir` on the harness process, and `permissions.additionalDirectories` in `~/.claude/settings.json`, in `<CLAUDE_PROJECT_DIR>/.claude/settings.json` and `settings.local.json` when the hook's environment sets `CLAUDE_PROJECT_DIR`, and in the event `cwd`'s `.claude/settings.json` and `settings.local.json` when that directory differs. A relative `--add-dir` resolves against the event's `cwd`. An `--add-dir` whose value cannot be resolved to an existing directory refuses the binding, `refused_by: unresolved-add-dir`.

**The descendant scan** reads `AGENTS.md` below each composed root to a depth of six, skipping `node_modules`, `__pycache__`, and any directory whose name starts with `.` (which covers `.git` and `.venv`), and not following symlinks. It visits at most 5,000 directories per root and refuses with `scan-cap` when the cap is reached. A declaration it finds refuses with `descendant`. The same session reuses that scan when `roots` is unchanged and the scan is less than ten minutes old. It does not cover a declaration deeper than six levels, one inside a dot directory, one reached only through a symlink, or one added within the reuse window. A tool also re-checks refusal at its material's own location. The gateway and `ask.mjs` re-check refusal at and above `owning_root` at the moment of sending.

**Trust boundary.** The binding stops the plugin's own code from sending for a session it cannot verify or whose roots refuse. It is not a defence against a host that deliberately works around it, which could equally read the key file.

**What a hook cannot know.** A directory added mid-session with `/add-dir` is not on the harness process's argument list and is not in the settings files the hook reads, so it is not in `roots`. A tool still checks its own material's location. **A gateway started with its own `--home` or `--env`** is not found, and the hook is then silent rather than wrong. **A harness that sets no `CLAUDE_PID` (Codex, Cursor) does not run these hooks, so it writes no binding, and every seam is silent there.** `ask.mjs` and a one-shot gateway process accept `CLAUDE_PID` only when that pid is an ancestor of the process that runs them (`not-ancestor` otherwise). The long-running gateway keeps its parent pid. The walk is `isAncestorPid` in `lib/binding.mjs`.

`lib/` holds what the hooks share: the binding, the presence and ownership checks, the roster built from the three family indexes, the one-shot gateway call, and the runner that keeps any error or timeout silent. `test/` runs offline: `WISER_HOOK_STUB_FILE`, a JSON file of answers by action id, stands in for the gateway, and is read only when that variable is set.
