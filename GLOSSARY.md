# Glossary

The words this plugin uses with a fixed meaning, each defined once here and used the same way everywhere. Where a file defines a term in full, it is named.

- **Wiser** is this plugin. **WISER** is the method behind a Playbook (`standards/playbook.md`); its five canons are Witness, Interrogate, Solve, Expand, Refine.
- **Plugin root** is the capability tree a harness loads, identified by its own `AGENTS.md` and scored in full by `standards/plugin-root.md`. Wiser is the **base plugin**; every other is a **domain plugin**, which loads beside the base, may assume it is present, and references its primitives and standards rather than duplicating them, per the constitution's Precedence and routing. `skills/Onboard Plugin Root/` creates a domain plugin or adopts a placeholder into that layout. A plugin root is not a user root: it holds capability, a user root holds work, and the phrase names the same tree that files here already point at with "at the plugin root" and "never in this plugin root". Producing that tree and deciding what it holds are two skills: `skills/Onboard Plugin Root/` makes the tree, and `skills/Scope Plugin Bench/` decides which experts, skills, tools and connectors go in its first slice.
- **The constitution** is `AGENTS.md` at this root. **The chain** is the sequence of `AGENTS.md` files a session loads: this one first, then the working folder's.
- **Working folder** is the folder you attach for the work: yours, your organization's, a client's, a department's, or an industry's. **User root** is the same folder seen as one of those five types, a folder carrying that declaration; `skills/Onboard Root/` creates a user root from the template, or adopts a folder that already holds work, against `standards/user-root.md`. **Owning root** is the attached root that owns the output of this session; with one folder attached, it is the working folder, and with several, the constitution's Workspace Model says which one. **Contract version** is the integer a root stamps in `layout:`. A user root's is defined in full by C1 of `standards/user-root.md`, and the named ask **update root** enters `skills/Housekeeping/` to compare that root's stamp against C1 and propose what is owed. A plugin root carries its own, defined in full by C1 of `standards/plugin-root.md`; the two authorities version on independent schedules, so a bump to one ages nothing under the other.
- **Primitive** is a skill, an expert, a tool, or a connector (`standards/primitives.md`). A **skill** produces something you ask for by name; an **expert** judges work through a perspective; a **tool** is a script that runs the same way every time, a classifier answer it asked for counted among its inputs. A **connector** is authenticated access to an outside platform, loaded by the **gateway**, the one local process a harness attaches over stdio. The named ask **set up connectors** is how a new harness, machine, or OS user attaches the gateway and confirms the project key; a missing vendor grant is still `needs_connect` and Connect Account. The vendor token never lives in a root.
- **Classifier** is the optional first-party service. The constitution's `## Classifier` defines it in full.
- **Classifier seam** is a closed judgment a classifier could answer for a primitive, put to it by code, with the path that settles it when none answers. Every new skill, expert and tool, and any file whose seam changes, declares its seams, or none, in one line of its Context. A typed file first written under an earlier version of `standards/primitives.md` may carry none until a change adds or alters a seam in it. `standards/primitives.md` Classifier Seam defines it in full.
- **Classifier trial** is the same cases run with the classifier on and off, interleaved, each run on a synthetic working folder with its own gateway home, scored blind against the primitive's Success lines, with the runs, cost and noise stated beside a verdict that releases nothing. `skills/Classifier Trial/` runs one; it is how the with-and-without test in `standards/primitives.md` Classifier Seam is run.
- **`needs_subscription`** is the gateway status meaning no classifier is loaded or the `WISER_CLASSIFIER_KEY` line is empty. `gateway/SETUP.md` section 5 defines it in full.
- **Memory** has three uses, and the context says which: the `memory:` line in a primitive's frontmatter lists the **abstract keys** it needs; the **Provides block** in a working folder's `AGENTS.md` binds each key to a file; and `memory/` is the directory in a user root where those files live. A key is **unscoped** when it resolves in the owning root and **scoped**, written `voice:org`, when it resolves in a root of that type.
- **Gap** is a capability this root does not provide that a primitive names as missing, declared in its `gaps:` frontmatter and collected in that root's own `system/GAPS.md`. An **honest stop** is what a primitive does when a step depends on a gap, an absent reading, or a tool that could not run: it says which step cannot run and what it would have produced, and produces nothing in its place; a run that stopped this way has done its work (the constitution's Behavioral Core).
- **Consent** is the question this plugin asks once per copy before any tool installs anything: it reports what it would fetch and stops, and the answer is `--install` on that run, or `WISER_ALLOW_INSTALL=1` for an unattended run. The answer is stored as `.wiser-consent` at the plugin root (`tools/RUNNING.md`).
- **Register** has two senses. The **sourcing register** of a claim is where it came from, public, firsthand, secondhand, or inference (`standards/conventions.md`). The **voice register** of a speaker is how formal or close their prose is, one of the things `voice.md` records. **Evidence labels** are the separate marks for how much checking a claim has had, also in `standards/conventions.md`.
- **Work directory** and **subject folder** are where output lands in the working folder: the directory that folder's `AGENTS.md` declares, and a folder inside it named for the subject (`standards/conventions.md`).
- **The Point-At Test** is Ghost Writer's test that every claim names something a reader could point at (`experts/Ghost Writer/EXPERT.md`).
- **Cognitive Layering** is Ghost Writer's rule that a piece builds each idea before the next needs it (`experts/Ghost Writer/EXPERT.md`).
- **A type file** is the file inside a writing skill that carries the rules for one kind of piece, such as `skills/Content Author/linkedin.md` for a post.
- **A change to a root** is a change to what a root holds or declares: this plugin's own files, or a user root's `AGENTS.md`, its bound memory files, its layout, or the addition of a root that does not exist yet. It is what `experts/System Expert/` gates before the skill runs, per the constitution's Precedence and routing. Work that a root merely *produces*, a deliverable in its work directory, is not one.
- **Play** is one instruction file for one repeatable outcome, owned by one root and complete enough that an agent handed nothing else can run it (`standards/play.md`). Unlike a skill, it is not shared across roots or routed to by the chain.
- **Playbook** is a plan for work that spans sessions, run by the WISER method, carrying its state, decisions, risks and learnings from one session to the next (`standards/playbook.md`). A One-time Playbook plans one piece of work; a Template Playbook is a master that each run copies to a dated instance.
- **`thoughts?`** asks for an assessment and authorizes no work, per the constitution's Behavioral Core.
- **`wrap up`** readies this session's Playbooks for the next one, per the constitution's Precedence and routing; `skills/Playbook Author/` owns what it does.
